# 0.7.0 完成记录：手机与无障碍（P5）

> 版本 0.7.0。对应路线图里的 P5「手机 / 无障碍」。
> 原则没变：只改显示层与交互层，不动 ILB 契约、不引第三方库、不写内联样式到布局数据里。

## 需求来源

P5 在 `P1-骨架计划.md:82` 只留了一句「手机端只保证不溢出，不专门做竖屏布局」，没有可执行的规格。
所以这一轮先做**实测审计**，按量出来的问题逐条修，不按想象修。

## 审计方法

`tmp/p5audit.mjs`（CDP，Edge headless，`Emulation.setDeviceMetricsOverride` 模拟手机）：

- 量面板几何、横向溢出、所有可交互元素的实际尺寸；
- 量代表性文字的对比度；
- 数 `:focus-visible` 规则、`role`、`aria-live` 区域、`prefers-reduced-motion` 规则；
- 比对 DOM 顺序与视觉顺序。

审计脚本自身也修过两个 bug（都导致过假数据）：

1. 对比度先把 `rgba(255,255,255,0.043)` 当成不透明背景算亮度，得出 `.dshui-cell-label` 2.63、`.dshui-cell-text` 1.84 这种「全都不合格」的假结论。改成沿祖先链按 alpha 逐层合成后，实际是 6.05 / 8.62。
2. 触控目标只报了 `< 44`，把「桌面紧凑档 28px」也当失败。现在同时报 `under24`（WCAG 2.2 AA 硬下限）和 `under44`（触摸屏建议值），分开看。

## 审计结论（390×844，修之前）

| 项 | 结果 |
|---|---|
| 横向溢出 | 无（`panelScrollW 366 == panelClientW 366`） |
| 对比度 | **全部通过 AA**：状态栏 6.75、格子标签 6.05、格子正文 8.62、脚注 6.75、变量名 13.23 |
| 触控目标 | **15 个低于 24×24**，最小 18px 高（`?` 24×18、`×` 23×22、列表项 23 高） |
| 焦点样式 | 全表只有 1 条（`.dshui-fab`），面板内所有控件键盘下无焦点环 |
| 语义 | 网格无 `role`、进度条无 `role`、`aria-live` 区域 **0** 个 |
| 减少动效 | 无 `prefers-reduced-motion` 规则，而 CSS 里有 `transition: right 160ms` 等 |
| DOM 顺序 | 与视觉顺序一致，无需重排 |

结论：**配色不用动**，要补的是触控尺寸、焦点、语义、播报、动效开关。

## 本轮做了什么

### 1. 触控目标

- 交互控件基线 `min-height: 28px`（高于 AA 的 24px 下限），图标按钮 `min-width: 28px`。
- `@media (pointer: coarse), (max-width: 640px)` 抬到 **44px**（Apple HIG）。
  两个条件都写：真机上 `pointer: coarse` 命中，桌面把窗口拉窄时靠宽度兜底。
- 覆盖：`?` / 编辑 / `×` / 布局下拉 / 页签 / 变量 chip / 列表项 / 小按钮 / 表单-JSON 页签。

### 2. 焦点可见

- `.dshui-root :is(button, select, input, textarea, [tabindex]):focus-visible` → `outline: 2px solid var(--dshui-accent); outline-offset: 2px`。
- 格子本身是 `button`，焦点环 `outline-offset: 1px` 贴边，少占位置。
- 用 `:focus-visible` 而不是 `:focus`：鼠标点完不出环，键盘用户才看到。

### 3. 语义

- 进度条：`role="progressbar"` + `aria-valuemin="0"` / `aria-valuemax="100"` / `aria-valuenow` / `aria-valuetext`（可读文本）/ `aria-label`（格子标签）。
- 网格：`role="group"` + `aria-label="页面：<页面标题>"`。
  没有用 `role="grid"`：那要求方向键在格子间移动，我们没实现，假语义比没语义更糟。

### 4. 播报

- 面板里常驻一个 `.dshui-sr-only`（视觉隐藏）节点：`role="status"` + `aria-live="polite"` + `aria-atomic="true"`。
- `setMsg()` 是**所有**动作结果的唯一出口（点格子、点列表项、保存、导入、切页……），在它里面调 `announce()`，所以每条结果都会念一句。
- 防刷屏：同一句话不重复写（`state.lastLive` 比对）。每次 `render()` 都会走 `setMsg` 之外的路径，不会因为重绘反复念。

### 5. 减少动效

- `@media (prefers-reduced-motion: reduce)` 把 `transition-duration` / `animation-duration` 压到 `0.01ms`，并关掉 `scroll-behavior: smooth`。

### 6. 键盘

- **Esc 两级**：有预览先退预览，没预览就关抽屉（以前 Esc 只退预览）。
- **焦点管理**：开抽屉焦点落到第一个可聚焦控件；关抽屉焦点回把手。
  首次加载恢复打开状态时不抢焦点（`applyOpen(false, false)`）。
- `collectFocusable()` 自己走 `children` 树收集，不依赖 `querySelectorAll`——这样测试桩里也能跑同一套逻辑。

### 审计复测（`tmp/p5audit.mjs`）

| 视口 | under24 | under44 | 横向溢出 | 网格 role | 进度条 role | aria-live | 减少动效规则 |

| 390×844 | 0 | 0 | 0 | group | progressbar | 1 | 有 |
| 1280×800 | 0 | 14 | 0 | group | progressbar | 1 | 有 |

桌面的 14 个「under44」是**故意的**：鼠标操作给 28px 紧凑档，仍高于 AA 的 24px；触摸屏和窄视口才抬到 44px。

### 行为验证（`tmp/a11yprobe.mjs`）

| 检查 | 结果 |
|---|---|
| 开抽屉后焦点 | `document.activeElement.className === "dshui-head-btn"`（进了面板） |
| 焦点环 | `matches(':focus-visible') === true`，`outlineWidth 2px`、`solid`、`rgb(122,162,255)`、`offset 2px` |
| 播报区 | `role=status`、`aria-live=polite`；点「金币 +1」后文本变成 `金币 → 4` |

## 已知边界

- 桌面 28px 仍是紧凑尺寸。想全程 44px 只能改窗口宽度或用触摸屏——这是有意取舍，不是漏做。
- `role="group"` 只给分组语义，**不支持方向键在格子间移动**。真做 `role="grid"` 需要一套完整的键盘导航和 roving tabindex，本轮没做。
- 播报只覆盖 `setMsg()` 的结果文案。变量在别处被改（ILB 其他入口）时不会主动播报，只更新界面。
- 变量 chip 点击是「点数字 +1」，读屏听到的是变量名和值，没有额外说明这是可点的加值按钮。
- `aria-live` 用 `polite`，连续快速点击时会排队念，不做合并。
