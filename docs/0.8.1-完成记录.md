# 0.8.1 完成记录：编辑态只留编辑器、手机键盘不再顶飞动作条、打字不再倒序

日期：2026-10-27　版本：0.8.1

## 一、用户报的四个问题（原文）

> 现在切换功能倒是实现了，可新的问题是在进行编辑时，手机端UI会随着虚拟键盘弹出被折叠导致画面变动，且会挡住画面看不清输入栏，而且在输入label时每次输入光标会自动移动到最前端，打出来的文本会变成字面意义上的倒叙。以及编辑页面顶端的UI预览依旧还在，显示而不是像之前所述那样编辑页面仅有编辑相关的控件，还会显示UI预览。我的想法是仅通过预览按钮进行预览，而不是实时显示，很多时候空间资源本就不多，这样就导致之前说的编辑时画面移动遮蔽的问题更严重了。主要是底部的预览、校验、应用等按钮会跟着键盘一起上移，加上顶部预览的存在，直接把画面盖住看不见了。

拆成四条：

| # | 现象 | 真因 |
| --- | --- | --- |
| 1 | 编辑时抽屉上半截还是界面预览 | `renderGrid()` 里有 `gridBox.style.display = 'grid'`，**内联样式盖过** CSS 的 `.dshui-body.is-editing .dshui-grid { display: none }` |
| 2 | 手机键盘弹起抽屉被折叠/输入栏被遮 | 面板高度固定用 `calc(100vh…)`，`100vh` 不含键盘；键盘弹起后可视区只剩一半，下半截被推到键盘背后 |
| 3 | 打 label 时光标跳回最前，字变成倒序 | 每次重绘都进 `renderForm()` → `clear(formBox)` 重建全部输入节点，光标被新节点复位到 0，再输入就插在最前面 |
| 4 | 底部「预览/校验/应用」跟着键盘上移盖住画面 | 动作条排在表单流里（`flex` 末尾），键盘一挤就被顶走；没有吸底 |

## 二、改法

### 1. 编辑态只留编辑器

- `src/panel.js`：删掉 `renderGrid()` 里那行内联 `display`，改成注释说明「浏览件显隐一律交给 CSS」。
- `src/panel.js` `renderEditor()`：除 `body.classList.toggle('is-editing', fullEditor)` 外，同时给**面板**加同名类 `panel.classList.toggle('is-editing', fullEditor)`。
- `style.css`：新增
  ```css
  .dshui-panel.is-editing .dshui-status,
  .dshui-panel.is-editing .dshui-toolbar { display: none; }
  ```
  于是编辑态下状态行、布局工具行、变量板、页签、网格、说明文字全部让位，编辑器吃满整块。

### 2. 手机键盘：按 `visualViewport` 算尺寸

- 新增 `applyViewport()`（`src/panel.js:480`）：
  - 面板打开时 `top = round(vv.offsetTop + 12)`，`height = max(240, round(vv.height - 24))`，直接写内联样式；
  - **抖动抑制**：变化不足 32px 就跳过，否则手机地址栏伸缩时抽屉会一直抽筋；
  - 面板关掉时清空内联 `top`/`height`，回到 CSS 的默认值。
- 监听三条：`visualViewport.resize`、`visualViewport.scroll`、`window.resize`（`src/panel.js:1809-1827`）。
- 新增 `revealFocus()`（`src/panel.js:508`）：键盘弹起 120ms 后对当前焦点元素 `scrollIntoView({ block: 'nearest' })`，把正在输入的框拉回视野；延迟是为了等键盘展开动画结束，否则算的是旧位置。

### 3. 动作条吸底

- 编辑器结构由 `hint / modeRow / (form+textarea+importBox 平铺) / issueBox / actions` 改为
  `hint / modeRow / **editorScroll**(form+textarea+importBox) / issueBox / actions`（`src/panel.js:253-255`）。
- `style.css`：`.dshui-editor-scroll { flex: 1 1 auto; min-height: 0; display: flex; flex-direction: column; gap: 6px }`，`.dshui-editor-actions { flex: 0 0 auto; border-top: … }`。
- 结果：只有中间那块滚，动作条钉在面板底部；面板高度已经按键盘上沿收过，所以动作条永远在键盘上方。

### 4. 打字不再重建表单

- `renderForm(force = false)` 加两道闸（`src/panel.js:965-979`）：
  1. `isTypingInside(formBox)`（`src/panel.js:409`）—— 焦点在表单里的 `input`/`textarea` 上就**直接 return**，一个节点都不动；
  2. `formKey()`（`src/panel.js:955`）—— 结构指纹 = `页码 # 选中项 # 页 id # grid JSON # cells 的 id:kind 序列`，指纹没变也 return。
- 结构动作（`↑`/`↓`/`删`/`＋ 页面`/`删除页`/切页签/点选控件/填入示例/导入）一律显式调 `renderForm(true)` 强制重建（共 10 处）；这些动作都会把焦点交给按钮，不会撞上第 1 条。
- 值变化（改标题、改数字、改 label）只走 `syncJson()`，不再重建。

## 五、已知边界

- **iOS Safari 未实测**：`visualViewport` 在 iOS 上是标准做法，但 iOS 键盘展开时 `offsetTop` 会随页面滚动变化，极端情况下抽屉可能被推下去一点；真机若仍有偏差，下一步换成「键盘弹起时切 `height:100dvh` + `top:0`」的兜底。
- 抖动抑制阈值 32px 是经验值：可视区变化小于 32px 时抽屉不动，小于该值的键盘（几乎没有）不会触发收缩。
- 编辑态下状态行与工具行是 `display:none`，键盘用户 Tab 也到不了——要切布局得先 `收起编辑` 或点 `预览`。这是「空间全给编辑器」的直接代价。
- 打字闸门按「焦点在表单内」判断：如果用户正在输入时别处触发重绘，表单会停在旧值直到失焦后下一次重绘（变量/网格仍是新的）。
