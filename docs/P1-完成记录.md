1. **`add` 动作由 UI 侧实现**（`src/api.js` 的 `addVar`：读 → 改 → 写），没有等 ILB 加 `add_var` 接口。
   理由：不阻塞 P1；ILB 若以后提供原子接口，只改 `src/api.js` 的 `addVar` 一处。

## 窄屏修复（2026-10-25 追加）

用户实测：PC 宽屏正常，**竖屏（窄视口）里 UI 完全不出现**。

根因（在真 ST 页面用 CDP 量出来，不是猜）：

- ST 在 `≤1000px` 时给 `body` 上了 `position: fixed`（`public/css/mobile-styles.css:250-254`）。body 脱离文档流后 `<html>` 的高度变成 **0**。
- 这个页面里 `<html>` 又带着一个单位 `transform`（computed 为 `matrix(1,0,0,1,0,0)`，页面里只有它，来源未定位到具体脚本），按 CSS 规范它因此成为 `position: fixed` 后代的包含块。
- 结果：`.dshui-panel { top:12px; bottom:12px }` 相对一个**高度为 0** 的包含块求解 → 实际高度 2px（只剩上下边框）；`.dshui-fab` 的 `bottom:12px` 把浮窗顶到视口上方。PC 宽屏下 `body` 是 static、`<html>` 高 800，所以看不出来。
- 证据：同页面新建一个 `position:fixed; inset:0` 的探针 div，量到高度 0；`height:100vh` 的探针量到 844。

修法（`style.css`）：不再用 `top`+`bottom` 拉伸，也不再用 `bottom` 定位浮窗，改成用视口高度算死：

```css
.dshui-panel { top: 12px; height: calc(100vh - 24px); height: calc(100dvh - 24px); }
.dshui-fab   { top: calc(100vh - 60px); top: calc(100dvh - 60px); }
@media (max-width: 520px) { … height: calc(100vh - 84px); … }
```

`dvh` 写在 `vh` 后面，不支持的浏览器自动回退。

验证（Edge headless + CDP，`tmp/shoot.mjs`，真 ST 页面 http://127.0.0.1:8100/）：

| 视口 | 抽屉高度 | 浮窗（收起态）位置 |
| --- | --- | --- |
| 390×844 | 760px（=844−84） | (334,788) 44×44，右下角 |
| 768×1024 | 1000px（=1024−24） | 右栏抽屉 |
| 1280×800 | 776px（=800−24） | 无回归 |

## 手动验收（ST 里）

1. 启动 SillyTavern，浏览器打开聊天页，刷新。
2. 右下角出现 ▦；点开是右侧抽屉，顶部状态行写着「接口 v1.0 · 书 N · 逻辑 M · 变量 K」。
3. 变量板里点数字变量 +1，下面网格里的对应数字同步变。
4. 网格里点「金币」格子 +1；点两次「喝药水」后按钮消失（`when 生命>0` 不再成立）。
5. 若没有变量：点「写入示例变量」，三枚种子变量落地后网格有内容。
6. 收起抽屉再刷新页面，抽屉保持收起；打开后刷新保持打开。
7. 把 ILB 停用再刷新：状态点变红，文字提示「ILB 未加载」，抽屉本身不崩。
