## 3. 这一轮修掉的坑

1. **DOM 桩的遍历顺序是“先父后子”**，`findByClass` 返回最外层节点，导致按钮测试点错元素；测试助手改为按 `textContent` 精确匹配 `button`。
2. **保存后的布局 id 撞车**：同一毫秒内保存两份会得到相同 id；改为 `layout-<时间36>-<随机4>`。
3. **`toggle` 变量不存在时**：不画成可点按钮（点了也不会凭空造变量），显示“未设置”并置灰；先点“写入示例变量”再玩。
4. **未保存的预览没有名字**：应用预览后下拉框仍显示“示例布局”，和状态行“布局：P2 检查”矛盾；现在多一个 `（未保存预览）` 选项，切走即丢弃草稿。
5. **stat 的副标题**：`label` 与 `var` 不同名时显示变量名（`甲` + `10` + `金币`），避免“甲=10”却不知道读的是哪个变量。

## 6. 手动验收（在 ST 里点一遍）

1. 刷新 ST（Ctrl+F5），右下角出现 ▦。
2. 点开 → “写入示例变量（金币 / 生命 / 心情 / 灯）”。
3. 点金币卡片：变量板里 `金币` +1；点“灯”：开/关切换；点列表里的“生命 -1”：`生命` 变化。
4. 点“编辑” → “填入示例” → “应用”：预览切到示例布局（未保存）。
5. 改标题 → “保存（全局）”：下拉框出现 `示例面板（全局）`，刷新后仍在。
6. 换一张角色卡 → “保存（角色卡）”：下拉框出现 `示例面板（角色卡）`；切回没有角色卡的聊天时仍能选到全局那份。
7. 粘贴一段坏 JSON → “校验”：逐条列出哪一格哪一项不对；点“应用”不生效。

## 7. 已知边界

- **`add` 只在 UI 侧原子**：api 同步，读改写之间不会插入别的调用；但两条逻辑同时写同一变量时仍是“后写赢”。
- **同名逻辑**：`call` 收到 `candidates` 时只展示候选，不做“让用户选一个再调”的交互；用户需把逻辑名写成 `书/逻辑` 或唯一名字。
- **role scope 的孤儿**：删掉角色卡后它名下的布局还在库里但选不中，P4 再做清理。
- **表单编辑器**：P3 才做；现在只有 JSON。
- **多页面**：不做，见决策记录 D-U12。
