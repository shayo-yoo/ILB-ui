# ILBUI 使用说明

> **ILBUI**（仓库名 dsh-ui）：一个把聊天变量渲染成网格界面的 SillyTavern 扩展。它负责“看得见、点得动”，不负责写规则；规则和变量归 ILB 管。
>
> 依赖：**ILB 0.12.0+**（`window.ILB.api` 接口 v1.1）。旧版 ILB（1.0）仍能打开，但 `call` / `open tab` / 结果回执这些联动能力不可用。

---

## 1. 它和 ILB 是什么关系

ILB 是“变量 + 规则 + 逻辑”的运行时，本扩展是它的一层**表现层**：

| 谁 | 负责 |
| --- | --- |
| ILB | 存变量、执行逻辑、维护世界书/规则，决定变量怎么变 |
| dsh-ui | 读变量、画格子、把点击翻译成「改变量 / 调逻辑 / 开面板」 |
| 你 | 用 JSON 或表单声明：哪个变量放在哪一格、长什么样、点了做什么 |
| AI | 只在**下一轮**看到变量变化；本扩展不改提示词、不碰上下文 |

因此典型闭环是：

```
AI 叙事 → ILB 写入变量 → dsh-ui 自动重画 → 你点按钮 → 变量变化
   ↑                                                      │
   └──────────── 下一轮 AI 读变量，继续叙事 ←─────────────┘
```

本扩展**不做**：表达式语言、`eval`、`innerHTML`、页面跳转历史、定时器刷新、直接改 AI 输出。

---

## 2. 安装与更新

1. 目录：`SillyTavern/public/scripts/extensions/third-party/dsh-ui/`（安装副本和源码目录结构一致）。
2. 依赖：先确保 `third-party/ILB` 存在且版本 ≥ 0.12.0。
3. 刷新：装好后按 **Ctrl+Shift+R** 强刷；抽屉标题栏右侧会显示版本号（例如 `v0.5.0`）。
4. 若版本号没变，说明浏览器用了缓存，再强刷一次；控制台里 `[dsh-ui]` 开头的报错会指明问题。

---

## 3. 打开、收起与把手

- 屏幕**右边缘**有一条半隐的竖把手（⋮），只露出约 12px；鼠标移上去会多露一点。
- **点一下**把手：展开抽屉，把手贴到抽屉左缘。
- **再点一下**：收起，把手回到右边缘。
- **按住上下拖**：换位置，松手后记住；拖到输入栏附近会自动停住，不挡输入框。
- 把手会自动避开 ILB 的悬浮球（不会叠在一起）。
- 抽屉标题栏：`●` 连接状态、版本号、`?` 使用说明、`编辑`、`×` 收起。

## 4. 变量：从哪来、怎么变

### 4.1 变量必须先存在

界面只渲染 `api.snapshot().vars` 里**已经存在**的变量。变量不存在时：

- 控件显示 `—`；
- 点击会提示「变量「xxx」不存在」，不会凭空创建。

给变量赋值的办法（任选）：

1. 在聊天里让 ILB 的规则/逻辑写入（例如你规则里约定的 `[[ILB:金币=10]]` 写法）；
2. 在 ILB 自己的面板里手动改变量；
3. 在本扩展里点 `add`/`set` 按钮（见第 8 节）。

### 4.2 自动重画

本扩展订阅 ILB 的变量变化事件：变量一变，界面就重画，不需要刷新页面。

### 4.3 UI 侧写回的边界

- `add`：读当前值 → 加/减 → 写回。**不是原子操作**，并发写以最后一次为准。
- `set`：直接写。
- `toggle`：布尔取反。
- 这些写入只改变量，**不会**触发 AI 回复；AI 下一轮才看得到。
- 只改已存在的变量；不会新建变量。

## 5. 快速上手（5 分钟）

1. 强刷 SillyTavern，确认右边缘出现 ⋮ 把手。
2. 让聊天里存在三个变量：`金币`（数字）、`生命`（数字）、`心情`（文字）。没有就先去 ILB 里设。
3. 点把手 → 点 `编辑` → 选 `表单` 页签。
4. 改标题、改网格列数/行数，点 `应用` 看预览；满意后点 `保存（全局）`。
5. 点 `收起编辑`，在网格里点按钮试试；底部会显示动作回执。

内置示例（`载入示例`）包含：金币/生命/心情三个状态、提示文本、喝药水按钮（`when 生命>0`）、捡金币按钮、背包页（列表 + 返回）。

## 6. 布局结构

一个布局就是一个 JSON 对象。最小结构：

```json
{
  "schema": "dshui/1",
  "title": "我的界面",
  "grid": { "cols": 4, "rows": 2 },
  "cells": [
    { "id": "gold", "kind": "stat", "label": "金币", "var": "金币", "area": [0, 0, 2, 1] }
  ]
}
```

### 6.1 顶层字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 布局名（显示在说明行） |
| `grid` | 是（或每页各自有） | `cols`/`rows` 必填；`gap`/`padding`/`minCellWidth`/`minCellHeight` 可选 |
| `cells` | 是（可为空） | 控件数组；也可写 `widgets` |
| `pages` | 否 | 多页面数组；每页 `{ id, title?, grid?, cells }` |
| `id` | 否 | 布局 id；导入/保存时由扩展分配 |

### 6.2 网格

- 坐标从 **0** 开始：`area: [列, 行, 跨列, 跨行]`。
- 越界（列+跨列 > cols 等）会**校验失败**；控件重叠只给 **warning**，不拦保存。
- 行高按内容自适应：某行全是文字按钮时不会长得离谱。

### 6.3 页面

```json
"pages": [
  { "id": "main", "title": "主界面", "cells": [ ... ] },
  { "id": "bag",  "title": "背包", "grid": { "cols": 4, "rows": 3 }, "cells": [ ... ] }
]
```

- 页面 `id` 必须唯一；不写 `grid` 就继承顶层 `grid`。
- 用 `open` 动作切页：`{ "kind": "open", "page": "bag" }`。
- 页面切换**不**自动提供“返回”，需要你自己放一个按钮。

## 7. 控件类型

| kind | 中文 | 主要字段 |
| --- | --- | --- |
| `stat` | 状态 | `var`、`label`、`prefix`、`suffix`、`decimals`、`when`、`onClick` |
| `text` | 文本 | `text`、`label` |
| `button` | 按钮 | `label`、`onClick`、`when` |
| `number` | 数字 | `var`、`label`、`prefix`、`suffix`、`decimals` |
| `bar` | 条形 | `var`、`max`、`label`、`suffix` |
| `toggle` | 开关 | `var`（布尔）、`label`、`onClick?` |
| `list` | 列表 | `items: [{ text, onClick? }]` |

通用字段：`id`（页内唯一）、`area`、`tone`（`tone-ok` / `tone-warn` / `tone-bad` 之类）、`clickable`。

表单里类型显示中文，**存进 JSON 的仍是英文 kind**（保证兼容与可分享）。

## 8. 点击动作

`onClick` 可以是单个对象，也可以是数组（按顺序执行，遇到错误继续后面的）。

| 动作 | 写法 | 行为 |
| --- | --- | --- |
| 设置 | `{ "kind": "set", "var": "心情", "value": "受伤" }` | 把变量设成字面值（数字/文字/true/false 自动识别） |
| 加减 | `{ "kind": "add", "var": "生命", "by": -10 }` | 数字加/减；变量必须存在且是数字 |
| 取反 | `{ "kind": "toggle", "var": "灯" }` | 布尔取反 |
| 调逻辑 | `{ "kind": "call", "logic": "获得", "args": { "物品": "药水", "数量": 1 } }` | 调 ILB 逻辑；成功/被拒/空结果三种回执 |
| 打开 | `{ "kind": "open", "page": "bag" }` 或 `{ "kind": "open", "tab": "rules" }` | 切本布局页面 / 开 ILB 自带面板标签 |

`open` 的可用标签：`shelf`、`rules`、`logic`、`snapshots`、`state`、`diagnostics`、`settings`。

`call` 的回执含义：

- **成功**：绿条，显示返回的 `extra` 摘要（如果有）；
- **被拒（blocked）**：黄条，显示 ILB 给的拒绝原因（常见是条件不满足）；
- **空结果**：灰条，逻辑执行了但没返回内容；
- 逻辑不存在：红条，列出同名候选或提示未找到。

示例：一次点击做两件事

```json
"onClick": [
  { "kind": "add", "var": "生命", "by": -10 },
  { "kind": "set", "var": "心情", "value": "受伤" }
]
```

---

## 9. 条件显示（when）

```json
{ "var": "生命", "op": ">", "value": 0 }
```

- 条件不满足：控件**不渲染**，自然点不到。
- 可用 `op`：`==` `!=` `<` `<=` `>` `>=` `含` `不含` `为空` `非空`。
- 数字比较会转数字；`为空` 判 `null`/`undefined`/空串。
- `when` 也能挂在 `list` 的每一项上。

---

## 10. 格式化

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| `prefix` | `"￥"` | 值前面的字 |
| `suffix` | `"G"` | 值后面的字 |
| `decimals` | `1` | 保留小数位（0-6） |
| `max` | `120` | 条形最大值；不写按 0-100 或变量范围估算 |

`stat`/`number` 的值会先转成人类可读文本：`null` → `—`，布尔 → `是/否`，空串 → `（空）`。

## 11. 表单编辑器

- 点 `编辑` → `表单`。进入编辑态后，状态行、布局工具行、变量板和网格**全部让位**，整块地方只给编辑器；界面的实时预览不会挤在上面——要看效果就点底部的 `预览`。
- **全局**：标题、列数/行数/间距/内边距。
- **页面**：选页面、页标题、`＋ 页面`、`删除页`（至少留一页）。
- **控件列表**：点一项选中，`↑`/`↓` 调顺序，`删` 删除。
- **控件详情**：类型、label、id、绑定的变量、文字、前后缀、小数位、area 四个数字、点击动作、`when`。
- **应用**：校验 + 预览（不落盘，标题旁标“未保存预览”）。
- **保存（全局）/ 保存（角色卡）**：进布局库。
- **预览按钮**（编辑器底部）：`按住` = 临时预览，松手回到编辑器；`点一下` = 进入交互预览，按钮会真的改变量，点预览栏里的 `返回编辑` 或按 `Esc` 退出。
- 预览是在抽屉**里面**换一块内容，不是一个盖住全屏的窗口：面板的标题栏、状态行、布局下拉、底栏都还在，所以随时能切布局、看回执。
- 底部那排 `预览`/`校验`/`应用`/`保存` 按钮是**吸底**的：手机键盘弹出时抽屉缩短到键盘上沿，这排按钮贴在键盘上方不动，表单在上半块里滚动；正在输入的字段会自动滚到能看见的位置。
- 打字时编辑器不会整块重画：改 label、改数字时焦点和光标都留在原地，不会出现“字被倒着打进去”。

---

## 12. JSON 页签与校验

- 点 `JSON` 直接改原始 JSON；`应用` 前先校验。
- 错误列表会指出路径与原因（例如 `cells[2].area 横向越界`），**不会**覆盖当前仓库。
- 可接受的旧写法（自动归一化）：`widgets`≈`cells`、`type`≈`kind`、`bind`≈`var`、单个 `action`≈`onClick`。
- `schema` 必须 `dshui/1`；布局太大（>64 控件/>12 页）会被拒。

---

## 13. 布局库、作用域与失效清理

- 存储位置：浏览器 `localStorage`（不写 `extension_settings`）。
  - 全局：`dshui.layouts.v2`
  - 角色卡：`dshui.role:<角色卡头像名>`
  - 界面状态：`dshui.ui.v1`
- 作用域：
  - 全局布局所有角色可见；
  - 角色卡布局只在该角色卡下出现，**优先于**全局；
  - 下拉里会标出当前布局属于哪个作用域。
- 切换布局：工具栏下拉选择；草稿预览显示“未保存预览”。
- 失效角色卡布局：角色删了/头像名变了，布局还在。点 `清除失效` 会**两段式**：先列出，再点一次确认才删。导入的布局**不会**自动保存。

## 14. 导入与导出

### 导出

- 生成一个 `.json` 下载，并提示文件名。
- 内容：`{ "schema": "dshui/1", "kind": "dshui-ui", "format": 1, "layout": { ... } }`
- 不含角色卡头像名，只包含布局。

### 导入

1. 点 `导入`，粘贴完整 JSON。
2. 扩展会校验结构、版本与字段；失败会指出原因。
3. 通过后进入**预览**，标题旁标“未保存预览”。
4. 你决定 `保存（全局）` 或 `保存（角色卡）`；也可以 `收起编辑` 直接点着玩。

> 导入是“不可信输入”：扩展不执行任何代码，只按字段渲染。

## 16. 和 ILB 配合的建议

1. **变量命名用中文、稳定**：`金币`、`生命`、`好感度`。改名会让布局失效（显示 `—`）。
2. **逻辑名要能被用户看懂**：`call` 里写逻辑名（如 `获得`），重名时扩展会列出候选，别用同名逻辑。
3. **动作要幂等/可重复**：按钮会被连点，逻辑里自己做上限判断（例如生命不超过 100）。
4. **不要让 UI 承担关键规则**：条件、掉落、判定放 ILB 逻辑里；UI 只负责触发。
5. **变量写回后 AI 才可见**：点完按钮不会立刻触发 AI 回复，别期待“点一下 AI 就说话”。
6. **ILB 面板标签**：`open` 的 `tab` 对应 ILB 的标签（书架/规则/逻辑/快照/状态/诊断/设置），具体可用项取决于 ILB 版本。

## 17. 常见问题

| 现象 | 可能原因 / 处理 |
| --- | --- |
| 右边缘没有把手 | 只露 12px，鼠标扫到最右侧；可能被别的浮窗盖住，拖一下换位置 |
| 界面完全没出来 | 控制台看 `[dsh-ui]` 报错；版本号不是最新就 Ctrl+Shift+R |
| 控件显示 `—` | 变量不存在（先去 ILB 创建）或名字写错 |
| 点了提示「变量不存在」 | 同上，`set`/`add` 不会新建变量 |
| 点了提示「逻辑未找到」 | `call.logic` 与 ILB 逻辑名不一致；看回执里的候选 |
| `call` 黄条「被拒」 | ILB 逻辑自身条件不满足，看它给的原因 |
| 导入报错 | 按错误里的路径改 JSON；先 `载入示例` 对照结构 |
| 布局在手机上看不全 | 页面可滚动；列数建议 4-6；把抽屉拉高或直接进预览 |
| 保存后换角色没了 | 存的是角色卡作用域；要跨角色用 `保存（全局）` |

## 18. 键盘、手机与读屏

### 键盘

| 操作 | 结果 |
| --- | --- |
| `Tab` / `Shift+Tab` | 在控件之间移动，当前控件有蓝色焦点环 |
| `Esc`（有预览时） | 退出预览，回到编辑 |
| `Esc`（无预览时） | 收起抽屉 |
| `Enter` / `空格` | 触发当前按钮；格子本身是 `button`，键盘天然可用 |

开抽屉时焦点会自动落到第一个控件上，收起时回到右边缘的把手——键盘和读屏用户不会「丢失当前位置」。
首次加载恢复上次展开状态时**不会**抢焦点。

### 手机 / 触摸屏

- 触摸屏（以及宽度 ≤640px 的窗口）下，按钮会放大到 44px 高，好按。
- 鼠标操作的桌面环境保持 28px 紧凑档，能多放内容。
- 布局本身**不会**自动改成竖屏排版：手机上的列数、行距还是按你声明的来。窄屏建议 4–6 列。
- 页面支持滚动，内容多不会溢出。

### 手机键盘

- 键盘弹出时抽屉会缩到**键盘上沿**（用 `visualViewport` 量真实可视高度，不靠猜），不会顶到键盘背后。
- 编辑态底部那排 `预览`/`校验`/`应用`/`保存（全局）` 是吸底的：键盘弹起后它们贴在键盘上方不动，只有上方的表单区在滚动。
- 正在输入的字段会在键盘弹出的瞬间被自动滚到视野内，不会被动作条盖住。
- 关掉键盘后抽屉恢复原来的高度和位置。

### 读屏

- 每条动作结果（点格子、点列表项、保存、导入、切页）都会写进一个 `aria-live` 区域，读屏会念出来——就是抽屉底部那行字。
- 进度条（`bar`）带 `role="progressbar"`，会念出当前值和上限。
- 网格是一个命名的分组，名字是「页面：<页面标题>」。
- 变量被别处改动时界面会更新，但**不会**主动播报（只播报你自己触发的动作结果）。

### 减少动态效果

系统里打开「减少动态效果」（`prefers-reduced-motion: reduce`）后，抽屉滑动、按钮变色等过渡会关掉。

## 19. 边界与安全

- 不做表达式求值、不用 `eval`/`innerHTML`/`new Function`；布局是用户输入，按不可信数据处理。
- 不读写 `extension_settings`；只用 `localStorage` 的三类键。
- 不改提示词、不插入消息、不调用生成接口；`call` 只调 ILB 暴露的逻辑。
- 布局体积有上限（64 控件/页、12 页），超大布局会被拒。
- 失效角色卡布局不自动删；导入布局不自动保存。
- 无网络请求、无遥测。
