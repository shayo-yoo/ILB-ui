## 1. 你们问的那一件（§5）：点 `ok` 按钮做什么

**只关掉这张卡片，不重调逻辑。** 我们从 0.10.0 起就是这么做的，现在也没变：

```js
findByClass(askBox, 'dshui-ask-ok').addEventListener('click', () => {
  askBox.hidden = true;      // 就这一句
  state.ask = null;
});
```

- 不调 `api.call`，不写变量，不重发指令——点一次真的只等于「我把这条提示读完了」。
- `ask.ok` 是**按钮文字**，不是动作名；我们把 `ok` 当纯文本用（截 12 字，超长加省略号），**不做任何求值**，也不允许它触发 `page`/`select`。
- 「点了才真正执行」我们按你们的建议拆两条逻辑：卡片只说明，真正的执行按钮由页面自己画（`onClick: { kind: 'call', logic: '实际执行' }`）。这个写法已经写进我们的使用说明 §16.5。

这条可以直接写进 ILB-4.21.7 的补充，我们这边不会再改。

## 2. §1.1 `page` 与 `select` 的优先级：已按你们的表实现

我们原来的做法是「`select` 找不到就自动翻到它所在的页」。按你们给的规则改成了三分支：

| 指令里有什么 | 界面现在做什么 |
|---|---|
| 只给 `page` | 翻到 `page`，不做别的 |
| 只给 `select` | 允许自己翻到那个控件所在的页再高亮（兜底，保留） |
| 两个都给 | 翻到 `page`；`select` **只在这一页上找**。找不到 → 不翻第二页，只在回执写一句「要聚焦的控件不在「背包」这一页里」 |
| 只给 `toast` / `ask` | 只提示，不动页面 |

实现上的判据是「这一条指令里到底有没有写 `page`」，而不是「切页有没有成功」——写了 `page` 但页面 id 不存在时，`select` 也不会成为翻页的理由。

## 3. §1.2 长度上限：一致，且照建议改成「截断 + 省略号」

- 我们自己也会兜底截断，但**不当错误报**，截完加 `…`（`slice(0, max - 1) + '…'`）。
- 现在用的表：`toast` 80、`page` 64、`select` 64、`ask.title` 40、`ask.text` 120、`ask.ok` 12——和你们的 `UI_LIMIT` 完全对齐。既然你们在保存阶段已经削平，我们这套只在「手写 JSON 直接塞进去」时才可能触发。

## 4. §1.3 版本演进：接受「逐条版本化」，不要求 `deprecated`

你们的三条规则我们照单接受，尤其是「能用 `v:1` 表达的指令永远发 `v:1`」——这让我们的 `ui.v === 1` 严格判定可以一直安全。遇到不认识的 `v`，我们**静默忽略**，不加警告（一条增强指令不该让整个界面报错）。

## 5. §2.2 采纳了 `id` 分桶，谢谢——确实是我们原来会踩的坑

- `seq` 的桶键从「逻辑名」换成 `res.id || res.name`（`id` 优先）。
- 你们举的两个场景我们都认：两本书同名逻辑、同一本书导出再导入。用名字分桶时，第二条逻辑的 `seq: 1` 会被第一条的 `1` 吞掉——界面就"这次没反应"。
- 兼容：老版本 ILB 不返回 `id` 时退化到 `name`，行为与 0.10.0 一致。

## 6. §3 `uiSkipped` 已经在界面上显示

回执里会多一句「已执行 · 界面指令被忽略：只有用户点按钮调用时才执行」（截 40 字）。我们不解析它的内部结构，只读第一个元素的 `.reason`，读不到就退化成字符串——**请你们把这个字段当稳定契约保留**，形状变了我们只会显示得更粗糙，不会崩。

## 7. 顺带问一句（不阻塞）

`uiSkipped` 现在只在我们主动 `call` 的返回值里出现。如果是**消息触发**的路径（`uiAllowed: false`），这次调用根本不经过界面，我们看不到任何东西——这种情况下用户永远不知道"书想让界面动一下但被拦了"。我们理解这是设计如此（界面不该被消息侧驱动），所以**不要求改**，只是想确认：这类被拦的指令除了 `steps` 里那条 `reason`，还有别的地方能看到吗？如果没有，我们就不做任何事。
